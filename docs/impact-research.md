# 영향 범위 — 연구 근거와 측정 (2026-10-28)

`impact` 도구와 커밋 직전 알림이 무엇에 기대고 있고, 무엇을 재서 무엇을 버렸는지. 숫자는 모두 이 레포의 벤치로 다시 낼 수 있다.

## 0. 결론

- **이력은 구조 도구에 없는 신호다.** 공변경·정의-참조·별칭 import를 합치면 정적 import 그래프만 쓸 때보다 같이 바뀔 파일을
  훨씬 잘 맞힌다(hit@5 0.353 → 0.586). 파서 의존성 없이 정규식으로.
- **의도가 핵심이다.** 같은 개념을 여러 계층에서 고치는 변경은 구조·이력으로는 수백 개 이웃과 구별되지 않는다. 작업 문장으로 찾은
  과거 커밋·파일을 합치면 R@10 0.393 → 0.460(p<0.0001). Ripple(ICSE 2026)의 "넓게 확장 → 의도로 정제"를 결정론으로 한 것이다.
- **자동 주입은 작업 성과를 바꾸지 못했다.** 커밋 직전 알림을 세 형태(엄격한 빠진 짝, 영향 후보, 의도 + 영향 후보)로 실제 수정 작업에
  넣어 봤지만 놓친 파일은 줄지 않았다(§6). 그래서 `impact`는 사람이나 에이전트가 **부를 때** 쓰는 도구로 둔다.
- **에이전트는 이유가 있으면 부른다.** 답이 다 적힌 수정 벤치에서는 grimoire 도구 호출이 0이었지만, 실제 세션 기록(10-26 이후
  165개 중 15개)에서는 221번 불렸다(record_note 109, search_memory 58). CLAUDE.md 지시와 이력 질문이 계기다. Claude Code의
  MCP 지연 로딩은 한 단계를 더하는 장벽이지 차단이 아니다.

## 1. 벤치 — `npm run impactbench`

이력 자체가 정답이다. first-parent 이력을 분할점에서 자르고, 분할 시점까지만 보이는 clone으로 색인한다(공변경뿐 아니라 import·정의·
파일 목록까지 분할 시점의 것). 분할 뒤 커밋(머지 제외, 파일 2~10개, 같은 변경 한 번)마다 파일 하나를 주고 나머지를 맞힌다.
Claude를 부르지 않아 질의 수백 개를 공짜로 돈다. code-review-graph의 "Impact Accuracy"와 같은 꼴이지만 정답을 사람이 만들지 않는다.

레포 6개(TS/React·Next.js·NestJS·C#), 분할 70%, 질의 864개 — 가중치를 고르는 데 쓰지 않은 분할:

| 근거 | hit@5 | R@10 | MRR |
|---|---|---|---|
| 같은 폴더 (기준선) | 0.216 | 0.152 | 0.134 |
| import + 2홉 (정적 그래프) | 0.356 | 0.225 | 0.222 |
| 공변경만 | 0.332 | 0.179 | 0.249 |
| 정의-참조만 | 0.446 | 0.253 | 0.276 |
| 전부 (기본값) | 0.586 | 0.393 | 0.432 |
| **전부 + 의도(커밋 제목)** | **0.637** | **0.460** | **0.452** |

- 경로 별칭(`@/components/x`)을 풀자 import만으로의 hit@5가 0.222 → 0.314. Next.js·Vite 레포는 거의 별칭으로 import한다.
- 정의-참조(Aider repo map식: 파일이 정의한 심볼 ↔ 다른 파일이 언급한 식별자)는 혼자서 가장 세다. import 문이 없는 C# 레포에서
  0.305 → 0.438. 다만 import와 같은 쌍을 겹쳐 세서, 합칠 때는 약하게(0.05) 둔다.
- 가중치는 거의 상관없다 — 54조합 그리드에서 MRR 0.383~0.390. 가르는 것은 어떤 근거를 켜느냐다.
- 의도는 실제 쓰임에서는 사용자의 요청이다. 벤치는 커밋 제목을 쓰므로 그보다 정보가 많을 수 있다.

## 2. 의도 합치기

다중 파일 fix 6개의 소스 20개를 하나씩 빼고 나머지로 순위를 보니, 상위 5위 안은 7개뿐이었다. 후보가 150~216개로 길고, 정답은 대부분
2홉 import만 있어 점수 0.1~0.35로 묻혔다(같은 개념을 가져오기·저장·내보내기에서 함께 고친 변경). 작업 문장으로 찾은 과거 커밋이
건드린 파일과 파일 검색을 RRF(k=20)로 합치면 그 20개의 중앙 순위가 22 → 6이 됐다.

구현은 `search()`가 아니라 FTS 질의 하나다(커밋·파일을 함께, BM25 순위 그대로, 발췌·재정렬 없음). `search()` 두 번 대비 1천 파일
레포에서 489ms → 5ms이고, 정확도도 높았다(R@10 0.433 → 0.460) — 사람이 읽을 결과를 위한 재정렬이 파일 후보 순위에는 맞지 않았다.
의도로만 찾은 파일은 점수 0으로 들어와, 점수 문턱을 쓰는 커밋 직전 알림은 흔들리지 않는다.

## 3. 커밋 직전 알림의 규칙

처음에는 영향 범위 점수에 문턱을 뒀다. 파일 하나 질의에서는 점수 0.8 이상의 57%가 같은 변경의 파일이었다. 하지만 커밋에는
파일이 여럿이라 근거가 쌓여 점수가 부풀고, 정답은 "빠뜨린 파일 하나"뿐이다. 실제 쓰임대로 다시 쟀다 — 분할 뒤 커밋을 그대로
두면(빠진 것 없음) 알림은 전부 오경보, 파일 하나를 빼고 커밋했다고 치면 그것을 되찾나 (레포 4개, 완전한 커밋 236개, 뺀 경우 849개):

| 규칙 | 완전한 커밋 오경보 | 빠진 파일 되찾음 | 알림 정밀도 |
|---|---|---|---|
| 영향 점수 ≥ 0.8 | 51% | 17% | 0.16 |
| 바뀐 파일별 최대 점수 ≥ 0.9 | 24% | 8% | 0.22 |
| 공변경 ≥ 0.7 · 지지도 ≥ 3 | 29% | 9% | 0.20 |
| **공변경 ≥ 0.9 · 지지도 ≥ 5 (채택)** | **5.5%** | 3.4% | **0.43** |

채택한 규칙을 실제 함수(missingCompanions)로, 가중치를 고르지 않은 분할에서 다시 재면(레포 6개): **오경보 2.5%, 되찾음 2.9%,
정밀도 0.57.** 드물게 울리고, 울리면 절반 넘게 맞는다. 놓친 파일을 많이 되찾는 도구는 아니다.

## 4. 버린 것

- **TARMAQ식 다중 시드 규칙**(질의와 겹침이 가장 큰 과거 거래로 규칙): 여러 파일 질의 123개에서 hit@5 0.398, 기본 noisy-OR 0.561.
- **공변경 신뢰도 사전값**(support/(touches+k)): MRR 0.382 → 0.372.
- **LLM이 공변경 순위를 매기게**: 학습 기반 순위 연구(2411.19099)에서 LLM은 맞지 않고 비싸다. LLM은 정제에 쓴다(§5).
- **LSP·Tree-sitter 호출 그래프**: 의존성이 무겁고 Serena·code-review-graph와 겹친다. 정규식 정의-참조로 대부분을 얻었다.
- **서버 안내문·도구 설명에 "커밋 전에 impact"**: 수정 벤치에서 호출 0/10씩, 결과도 같았다. 매 커밋 호출 비용만 늘어 뺐다.
- **커밋 직전 영향 후보 자동 주입**(`GRIMOIRE_COMMIT_IMPACT=all`): §6. 실험 장치로만 남긴다.

## 5. LLM 정제 (오프라인)

질의 60개(레포 4개)에 후보 15개 + 시드 diff + 커밋 제목을 주고 sonnet이 고르게 했다(호출 180회). F1 0.16 → 0.26(상위 5 대비
p=0.017), 정밀도 0.14 → 0.65. 고른 개수를 맞춘 순위 자르기(0.16)보다 높아, 이득은 순위가 아니라 고르기에서 나왔다. 의도를 빼면 0.19,
점수·이유를 빼면 0.24(p=0.21).

## 6. 실제 작업 (taskbench `--commit`)

시간 마스킹 누수(작업 worktree를 원본 레포에서 만들어 실제 fix가 색인과 `git log --all`에 보이던 것)를 고친 뒤의 측정이다.

**TerraLink 사례 5개 × 2** — 놓친 파일이 색인 대상이 아닌 픽스처라 개선 여지가 없었다. 비용비 0.972(p=0.67), 알림 0회.

**소스 2~5개를 고친 fix 6개 × 2** (`--mine --min-files 2`, 조건마다 12회, 6개 조각 병렬):

| 조건 | 통과율 | 놓친 파일 | 엉뚱한 파일 | 해결당 비용 | 알린 것 중 실제 fix 파일 |
|---|---|---|---|---|---|
| bare | 0.42 | 2.08 | 0.50 | $0.834 | – |
| grimoire (엄격 알림) | 0.42 | 2.33 | 0.17 | $0.799 | 0회 울림 |
| 영향 후보 주입 | 0.42 | 2.00 | 0.25 | $0.936 | 0/22 |
| 의도 + 영향 후보 주입 | 0.42 | 2.42 | 0.50 | $0.859 | 2/26 |

어느 조건도 bare와 유의한 차이가 없다(놓친 파일 p ≥ 0.14). 에이전트가 실제로 놓치는 파일은 영향 상위 5개 밖에 있었다.
오프라인 재현율 개선은 이 어려운 누락까지 닿지 않는다.

## 7. 실험 장치에서 고친 것

- 시간 마스킹 누수 → 부모까지만 보이는 clone(`pinnedClone`)에서 worktree를 만든다.
- fix가 새로 만든 테스트 파일은 부모에 없다 → 회귀는 부모에 있던 테스트만으로 잰다.
- 에이전트가 남긴 git 프로세스의 `index.lock` → 채점의 git 호출이 최대 10초 기다렸다 다시 한다.
- `npm run`이 `--test "cd x && …"`의 따옴표를 벗긴다 → 채굴은 `node .test-out/e2e/taskbench.js`로 직접.
- `--commit`(끝에 커밋), `--hook-env`, `--tool-desc`(벤치 전용 설명 바꿔 끼우기), `--min-files`, 조각 병렬 실행(`--only`).
