# 영향 범위 — 연구 근거와 측정 (2026-10-28)

`impact` 도구와 커밋 직전 알림이 무엇에 기대고 있고, 무엇을 재서 무엇을 버렸는지. 숫자는 모두 이 레포의 벤치로 다시 낼 수 있다.

## 0. 결론

- **에이전트가 부르기를 기다리지 않는다.** 편집 직전 카드(0.8.x)와 MCP 도구는 측정에서 효과가 없거나(비용비 0.93·0.97, p=0.48·0.78)
  아예 불리지 않았다(0/20). MCP 도구 선택 연구도 같은 쪽을 가리킨다 — 에이전트는 메타데이터로 고르고, 덜 알려진 도구는 덜 쓴다.
- **grimoire의 일은 후보를 넓게 내는 것, 고르는 일은 의도를 아는 쪽이 한다.** Ripple(ICSE 2026)의 2단계(결합으로 확장 → LLM이
  변경 계획으로 정제)를 우리 데이터로 재현했다: 의도와 함께 거르면 F1 0.16 → 0.26, 정밀도 0.14 → 0.65 (p=0.017). 의도를 빼면 0.19.
- **이력은 구조 도구에 없는 신호다.** 공변경을 더하면 정적 그래프만 쓸 때보다 맞힌다. 구조 쪽(정의-참조, 별칭 import)도 정규식으로
  싸게 보강할 수 있다 — 파서 의존성 없이.

## 1. 벤치 — `npm run impactbench`

이력 자체가 정답이다. first-parent 이력을 분할점에서 자르고, 분할 시점까지만 보이는 clone으로 색인한다(공변경뿐 아니라 import·정의·
파일 목록까지 분할 시점의 것). 분할 뒤 커밋(머지 제외, 파일 2~10개, 같은 변경 한 번)마다 파일 하나를 주고 나머지를 맞힌다.
Claude를 부르지 않아 수천 질의를 공짜로 돈다. code-review-graph의 "Impact Accuracy"와 같은 꼴이지만 정답을 사람이 만들지 않는다.

레포 6개(TS/React·Next.js·NestJS·C#), 분할 70%, 질의 868개 — 가중치를 고르는 데 쓰지 않은 분할:

| 근거 | hit@5 | R@10 | MRR |
|---|---|---|---|
| 같은 폴더 (기준선) | 0.218 | 0.155 | 0.130 |
| import + 2홉 (정적 그래프) | 0.353 | 0.227 | 0.220 |
| 공변경만 | 0.333 | 0.179 | 0.250 |
| 정의-참조만 | 0.444 | 0.254 | 0.277 |
| 정의-참조·형제 빼고 전부 | 0.543 | 0.371 | 0.399 |
| **전부 (기본값)** | **0.581** | **0.394** | **0.429** |

- 경로 별칭(`@/components/x`)을 풀자 import만으로의 hit@5가 0.222 → 0.314 (분할 80%). Next.js·Vite 레포는 거의 별칭으로 import한다.
- 정의-참조(Aider repo map식: 파일이 정의한 심볼 ↔ 다른 파일이 언급한 식별자)는 혼자서 가장 세다. import 문이 없는 C# 레포에서
  0.305 → 0.438. 다만 import와 같은 쌍을 겹쳐 세서, 합칠 때는 약하게(0.05) 둔다.
- 가중치는 거의 상관없다 — 54조합 그리드에서 MRR 0.383~0.390. 가르는 것은 어떤 근거를 켜느냐다.
- 속도: 1천 파일 레포에서 질의당 12.7ms (정의-참조 질의를 이름마다 한 번만 세게 고쳐 20ms → 9ms).

## 2. 커밋 직전 알림의 문턱

파일 하나 질의에서 점수 문턱별 정밀도(알린 것 중 실제로 같은 변경에 들어간 비율):

| 문턱 | 정밀도 | 알린 질의 비율 | 질의당 알린 수 |
|---|---|---|---|
| 0.5 | 0.30 | 53% | 1.24 |
| 0.7 | 0.46 | 30% | 0.45 |
| **0.8** | **0.57** | **21%** | **0.26** |
| 0.9 | 0.59 | 14% | 0.17 |

0.8에서 대부분의 커밋은 조용하고, 알릴 때는 절반 넘게 맞는다. 고르는 일은 에이전트에게 — 의도를 이미 안다.

## 3. 버린 것

- **TARMAQ식 다중 시드 규칙**(질의와 겹침이 가장 큰 과거 거래로 규칙): 여러 파일 질의 123개에서 hit@5 0.398, 기본 noisy-OR 0.561.
- **공변경 신뢰도 사전값**(support/(touches+k)): MRR 0.382 → 0.372.
- **LLM이 공변경 순위를 매기게**: 학습 기반 순위 연구(2411.19099)에서 LLM은 맞지 않고 비싸다. LLM은 정제(§0)에 쓴다.
- **LSP·Tree-sitter 호출 그래프**: 의존성이 무겁고 Serena·code-review-graph와 겹친다. 정규식 정의-참조로 대부분을 얻었다.

## 4. 남은 것

- 1단계 재현율: LLM 정제 실험에서 후보 15개 안에 정답이 없는 질의가 40%였다(정의-참조·별칭 전). 백엔드 라우트 ↔ 프런트 화면처럼
  문자열 API 경로로만 이어진 쌍은 아직 못 잇는다.
- 커밋 직전 알림이 실제 작업에서 놓친 파일(taskbench `missed`)을 줄이는지는 아직 재지 않았다.
